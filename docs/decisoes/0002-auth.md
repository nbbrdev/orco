# ADR-0002 — Autenticação

- **Status:** **substituído** pelo [ADR-0013](0013-auth-better-auth.md) na parte do provedor (2026-09-29)
- **Data:** 2026-09-27

> **Revisão (2026-09-29):** o Supabase Auth dá lugar ao **Better Auth** ([ADR-0013](0013-auth-better-auth.md)), e o SMTP do painel dá lugar ao envio pelo app ([ADR-0016](0016-email-smtp.md)). **Continuam valendo** as regras de produto deste ADR: e-mail + senha com confirmação, Google, senha mínima de 8 sem exigência de tipos, Turnstile só no cadastro, sem magic link nem MFA e os riscos aceitos.

## Contexto
Cadastro aberto ao público; o princípio central é simplicidade. É preciso proteção contra bots e nenhuma responsabilidade própria sobre guarda de senhas.

## Decisão
- **Supabase Auth** como único provedor de identidade. Senhas com hash **bcrypt** feito pelo Supabase, no schema `auth`. O app nunca manipula hash de senha.
- Métodos: **e-mail + senha** (confirmação obrigatória, **mínimo 8 caracteres sem exigência de tipos**, escolha do usuário para reduzir o atrito no cadastro) e **Google OAuth**.
- **Cloudflare Turnstile somente no cadastro**, que é onde bots criam contas e gastam a cota de e-mail (decidido pelo usuário). A opção nativa do Supabase exige CAPTCHA em todos os endpoints de auth, por isso fica desligada: a Server Action de cadastro valida o token na API `siteverify` da Cloudflare antes de chamar `signUp`. Login e recuperação dependem do rate limit nativo do Supabase Auth; o CAPTCHA pode ser estendido a eles se houver abuso.
- **Resend** como SMTP do Supabase Auth, com remetente no domínio próprio. O SMTP padrão do Supabase é limitado demais para produção.
- Sessão por cookies `@supabase/ssr`; autorização no servidor sempre com `getUser()`/`getClaims()`.
- Fora: magic link e MFA (reavaliar pós-MVP).

## Consequências
- Zero código de criptografia de senha para manter.
- **Risco aceito:** senhas fracas (ex.: `12345678`) são permitidas e a proteção contra senhas vazadas é recurso pago. Mitigações: rate limit de login do Supabase e o Google como alternativa sem senha. Reavaliar na M7 (ex.: bloquear uma lista das senhas mais comuns no client).
- Dependência do Resend (plano Free: 3.000/mês, 100/dia), o que é suficiente para o MVP.
- Google exige tela de consentimento configurada, com links de termos e privacidade.
